# Discovered Rules — Asset Tracker MVP

> FINAL. Written by the Practices Discovery lead. Every rule below is
> traceable to a source: a standing condition from the approved decision set,
> a workbook section, one of the human's 22 interview answers, or a
> support-review finding the human affirmed. No rule is invented.
>
> **Where these rules land.** Per the human's answer to Q21, product-behaviour
> contracts belong to the project file and working practices belong to the
> team file. The promotion tool cannot split them: `aidlc-state.ts
> practices-promote` appends **every** rule in this file's `## Mandated` and
> `## Forbidden` sections to `project.md`'s `## Mandated` and `## Forbidden`,
> and takes the working practices from `team-practices.md`'s five team
> sections. So this file carries **only** the rules that belong in
> `project.md` — the product-behaviour contracts — and the working practices
> live in `team-practices.md`. The bucket each rule falls into is named
> inline.
>
> **Format constraint.** The promotion tool parses each rule as one line and
> appends it verbatim with an `(affirmed YYYY-MM-DD)` stamp. A rule wrapped
> across lines would be split into two malformed rules, so every rule below
> is a single line.

The `## Mandated` and `## Forbidden` sections below are rules the *human* has
stated as hard constraints, either directly in the interview or by approving
the decision set that carries them. Where a rule's source is the approved
decision set, the standing conditions, or an upstream Ideation answer, the
source is named inline.

## Mandated

- ALWAYS preserve the existing 66/66 passing test baseline and add regression tests for newly approved behaviour alongside it, never in place of it. (Bucket: project — product-behaviour contract. Source: the approved 17-item decision set's standing conditions, carried in `aidlc/spaces/default/memory/project.md` `## Decided`; the `feature` scope's standing merge gate; and the human's Q9 answer that every new test carries its requirement identifier.)
- ALWAYS resolve actor identity from trusted server-side context, and ALWAYS ignore a request-supplied actor rather than rejecting or sanitising it. (Bucket: project — product-behaviour contract. Source: the approved decision set, workbook section 4.3 — the actor-trust rule — as recorded in `aidlc/spaces/default/memory/project.md` `## Decided`; and the human's Q20 answer.)
- NEVER use a client-settable field or header as the actor's source, whichever actor mechanism is ultimately chosen. (Bucket: project — the negative specification of the actor-trust rule, stated by the human in Q20 and compatible with all four mechanism candidates.)
- ALWAYS use one shared definition for the functional-index expression and the application-level comparison predicate in the uniqueness check, and ALWAYS apply the same uniqueness policy to registration and to serial/key updates. (Bucket: project — product-behaviour contract. Source: the approved decision set's standing conditions, as recorded in `aidlc/spaces/default/memory/project.md` `## Decided`.)
- ALWAYS perform the uniqueness check inside an `IMMEDIATE` transaction with a non-zero SQLite `busy_timeout`, and ALWAYS map `SQLITE_BUSY` to a retryable error. (Bucket: project — product-behaviour contract. Source: the approved decision set's standing conditions, as recorded in `aidlc/spaces/default/memory/project.md` `## Decided`.)
- ALWAYS detect a SQLite error by its machine-readable `err.code` (`SQLITE_CONSTRAINT_UNIQUE`, `SQLITE_BUSY`) and NEVER by matching `err.message` text. (Bucket: project — the discriminator the uniqueness and retry standing conditions depend on. Source: the developer review's live verification of `better-sqlite3` error codes and the existing message-text match at `src/repositories/assets-repo.js:70`.)
- ALWAYS provide a retryable domain error code, because none of the current five codes (`VALIDATION_ERROR`, `DUPLICATE_ASSET`, `NOT_FOUND`, `INVALID_TRANSITION`, `INVALID_STATE`) is retryable and the `SQLITE_BUSY` mapping requires one. (Bucket: project — product-behaviour contract. Source: the `SQLITE_BUSY` standing condition, plus the developer review's finding on the error vocabulary.)
- ALWAYS preserve original records and audit traceability in historical backfills, and ALWAYS report backfill failures. (Bucket: project — product-behaviour contract. Source: the approved decision set's standing conditions, as recorded in `aidlc/spaces/default/memory/project.md` `## Decided`.)
- ALWAYS compute dashboard, assignee-directory, asset-list, and CSV counts from one shared filtering and counting definition, so the four count-consuming surfaces agree with each other. (Bucket: project — product-behaviour contract. Source: the approved decision set's standing conditions, as recorded in `aidlc/spaces/default/memory/project.md` `## Decided`.)
- ALWAYS give every lifecycle transition explicit validation and explicit audit behaviour. (Bucket: project — product-behaviour contract. Source: the approved decision set's standing conditions, as recorded in `aidlc/spaces/default/memory/project.md` `## Decided`.)
- ALWAYS write the asset update and its audit append as one transaction, so a failure cannot leave a mutated asset with no audit row. (Bucket: project — the enforcement form of the explicit-audit-behaviour standing condition, required for Audit Completeness to be achievable. Source: the devsecops review's finding on the two separate statements in `src/services/asset-service.js`.)
- ALWAYS enforce append-only audit history with SQLite `BEFORE UPDATE` and `BEFORE DELETE` triggers installed by the `audit_log` rebuild migration, so the guarantee does not depend on application code. (Bucket: project — the enforcement form of the append-only history invariant. Source: the human's Q17 answer, and the devsecops review's live verification that both triggers work and that the `BEFORE DELETE` trigger also blocks the destructive cascade.)
- ALWAYS record the `lost → in-stock` recovery as a distinct `recovered` audit action rather than as `assign` or `return`, and ALWAYS name the recovery and the prior holder in that action's description. (Bucket: project — product-behaviour contract. Source: workbook section 4.1 as amended, as recorded in `aidlc/spaces/default/memory/project.md` `## Decided`.)
- ALWAYS resolve the assignment inline on the `assigned → discarded` transition: clear `assigned_to`, retain `last_assigned_to` so the holder at discard time stays visible, and record the discard, the prior holder, and the fact that the assignment was resolved by the discard in a `discarded` audit action. (Bucket: project — product-behaviour contract. Source: workbook section 4.1 as amended, as recorded in `aidlc/spaces/default/memory/project.md` `## Decided`.)
- ALWAYS require a reason for a discard and for a recovery, drawn from the shared loss-reason vocabulary plus the retirement-specific values. (Bucket: project — product-behaviour contract. Source: workbook section 4.1 as amended, as recorded in `aidlc/spaces/default/memory/project.md` `## Decided`.)
- ALWAYS exclude pre-MVP backfilled history from the Audit Completeness metric, because that history is backfilled to a `system` actor. (Bucket: project — product-behaviour contract. Source: workbook section 24 as amended — the metric qualifier is carried verbatim in `aidlc/spaces/default/memory/project.md` `## Decided`.)
- ALWAYS maintain traceability between the approved MVP requirements and the POC requirements FR1.3, FR4.4, FR4.5, and FR5.3. (Bucket: project — product-behaviour contract. Source: the approved decision set's standing conditions, as recorded in `aidlc/spaces/default/memory/project.md` `## Decided`.)
- ALWAYS treat the approved 17-item decision set and the Asset Tracker MVP Development Workbook as the binding technical and product contract for this intent. (Bucket: project — product-behaviour contract. Source: `aidlc/spaces/default/memory/project.md` `## Decided` — recorded as "not reopened at any stage of that intent".)
- ALWAYS preserve POC behaviour that the MVP does not explicitly cover, except where it conflicts with an approved invariant — append-only history, the five exclusive status buckets, or the shared counting definition — and ALWAYS record the retirement of any conflicting POC behaviour. (Bucket: project — product-behaviour contract. Source: the intent backlog's `[Q8]` answer, recorded in `aidlc/spaces/default/intents/261106-asset-tracker-mvp/ideation/scope-definition/intent-backlog.md`.)
- ALWAYS treat the foundation workstream as a hard predecessor of every other capability, and ALWAYS ship the four count-consuming surfaces — dashboard, assignee directory, asset list, CSV export — as one indivisible group. (Bucket: project — product-behaviour contract. Source: the intent backlog's `[Q3]` answer, recorded in `aidlc/spaces/default/intents/261106-asset-tracker-mvp/ideation/scope-definition/intent-backlog.md`.)
- ALWAYS resolve the actor-identity mechanism before the foundation is built, and treat the actor-identity decision and the `audit_log` rebuild as one indivisible workstream. (Bucket: project — product-behaviour contract. Source: the intent backlog's `[Q6]` answer and the team assessment's `[Q6]` answer, recorded in `aidlc/spaces/default/intents/261106-asset-tracker-mvp/ideation/scope-definition/intent-backlog.md` and `.../ideation/team-formation/team-assessment.md`; reinforced by the devsecops review's finding that `audit_log` has no actor column and `recordAudit` has no actor parameter.)
- ALWAYS take a design-board checkpoint before the foundation is built, and ALWAYS record the architectural decisions as ADRs. (Bucket: project — product-behaviour contract. Source: the team assessment's `[Q5]` answer and the team's mitigation for single-developer concentration risk, recorded in `aidlc/spaces/default/intents/261106-asset-tracker-mvp/ideation/team-formation/team-assessment.md`.)
- ALWAYS deploy to the same single internal host with a machine-local SQLite file, launched as a long-running process. (Bucket: project — the product-behaviour contract that fixes the release's deployment target. Source: the feasibility assessment's `[Q6]` answer, recorded in `aidlc/spaces/default/intents/261106-asset-tracker-mvp/ideation/feasibility/feasibility-assessment.md`.)
- ALWAYS assert on `err.code` and NEVER on error message text, in application code and in tests. (Bucket: project — the assertion discipline that makes the domain and driver error contracts testable. Source: the developer review's finding that a message-coupled test cannot distinguish a functional-index violation from a plain one.)
- ALWAYS seed a migration or rebuild fixture with representative rows in every table the migration touches, including `audit_log`, and ALWAYS assert the post-migration row count and contents of those rows. (Bucket: project — a product-behaviour contract on test fixtures, stated by the human in Q8: a migration test must run against a database populated with audit history and assert the history survives.)
- ALWAYS apply one shared CSV export-escaping function to every string cell, covering a leading `=`, `+`, `-`, `@`, tab, or carriage return. (Bucket: project — the product-behaviour contract for the MVP's mandated CSV export. Source: the human's Q18 answer, and the devsecops review's finding that the protection is otherwise unimplemented.)

## Forbidden

- NEVER trust actor information supplied in a write request; the actor is always resolved from trusted server-side context. (Bucket: project — product-behaviour contract. Source: the approved decision set, workbook section 4.3 — the actor-trust rule — as recorded in `aidlc/spaces/default/memory/project.md` `## Decided`. This is the negative form of the same rule that appears in `## Mandated`.)
- NEVER delete an asset row or its history; a discarded asset is excluded from Active Inventory but remains in the `discarded` bucket and in Total Records, and stays accessible at its detail URL with its history intact. (Bucket: project — product-behaviour contract. Source: workbook section 4.1 as amended, as recorded in `aidlc/spaces/default/memory/project.md` `## Decided`.)
- NEVER record a recovery as an `assign` or a `return` audit action. (Bucket: project — product-behaviour contract. Source: workbook section 4.1 as amended, as recorded in `aidlc/spaces/default/memory/project.md` `## Decided`.)
- NEVER destroy audit history. (Bucket: project — product-behaviour contract. Source: the MVP's own approved invariant that history is never destroyed — Audit Completeness is the intent's primary success measure, recorded in the intent backlog's `[Q2]` answer.)
- NEVER drop a table that another table references with `ON DELETE CASCADE` while the referencing rows exist; a table rebuild must rebuild the referencing table first, without its foreign-key clause, and re-add the foreign key afterwards. (Bucket: project — the general form of the append-only-history invariant, applying to every schema change in this repository and not only to the MVP's rebuild. Source: the verified migration-ordering constraint in `aidlc/spaces/default/codekb/assets_management/architecture.md` and the developer review's finding that a one-off ordering instruction goes stale.)
- NEVER let the four count-consuming surfaces ship with divergent counts; a group that ships all but one of its members has no consistency guarantee at all, so the four surfaces are never split across increments. (Bucket: project — product-behaviour contract. Source: the intent backlog's `[Q3]` answer, recorded in `aidlc/spaces/default/intents/261106-asset-tracker-mvp/ideation/scope-definition/intent-backlog.md` and the scope-definition stage's recorded interpretation.)
- NEVER reopen the approved decision set, the workbook, or the scope boundary at any stage of this intent; a change requires a new approval round. (Bucket: project — product-behaviour contract. Source: the scope-definition stage's `[Q6]` answer — "Scope is fixed for this MVP" — and the `## Decided` record in `aidlc/spaces/default/memory/project.md`.)
- NEVER ship partial recovery workflows — partial recovery, credit assignment, dispute handling — in this release; only the single included recovery transition is in scope. (Bucket: project — product-behaviour contract. Source: workbook section 4.1 as amended, as recorded in `aidlc/spaces/default/memory/project.md` `## Decided`.)
- NEVER let the design system, responsive UI, improved search, pagination and result counts, or empty states into this release; they are deliverable in a later increment. (Bucket: project — product-behaviour contract. Source: the intent backlog's `[Q2]` answer, recorded in `aidlc/spaces/default/intents/261106-asset-tracker-mvp/ideation/scope-definition/intent-backlog.md`.)
- NEVER allow an audit row to be updated or deleted; the `audit_log` table rejects `UPDATE` and `DELETE` at the database level. (Bucket: project — the enforcement form of the append-only-history invariant, stated by the human in Q17 and verified by the devsecops review.)
- NEVER export a CSV cell that begins with `=`, `+`, `-`, `@`, tab, or carriage return without the formula-injection prefix, in any column. (Bucket: project — product-behaviour contract. Source: the human's Q18 answer.)
