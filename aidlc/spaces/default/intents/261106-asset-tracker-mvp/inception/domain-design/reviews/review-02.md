### Notes

This pass judges the **current** artefacts on their own merits; the eight findings of the previous pass were treated as closed questions and their fixes were checked for coherence rather than presence.

**The eight previous findings are, on the whole, genuinely fixed and the fixes are coherent.** I verified each independently rather than by reading the prose:

- **R-01 (error vocabulary unowned) — fixed.** `DomainVocabulary` now owns "the domain error-code vocabulary of exactly nine values, with each code's HTTP status and its retryable flag" (components.md:50), `ErrorTranslation` is a separate component with the single translation point, ADR-012 records the decision with alternatives, and the nine codes are written out literally in `## Error Vocabulary` with their statuses and retryable flags. The `INVALID_STATE` gap the team practice requires is closed (it is mapped to 400; I confirmed against `src/app.js:20` that the current middleware omits it, so the claim is accurate). The vocabulary's *content* is now the subject of R-1 above, but the ownership and the literal binding are done.
- **R-02 (advisory lookup taking a write lock) — fixed and correctly.** `UniquenessCheck` now names two transaction disciplines explicitly — the authoritative check "inside an immediate transaction with a non-zero busy timeout" and the advisory lookup "inside a deferred read transaction and takes no write lock" — with the rationale stated in the component's behaviour and in ADR-008. The rationale is also technically right: an `IMMEDIATE` transaction on the single shared SQLite file would take a RESERVED write lock on every form blur.
- **R-03 (five-dimension filter cannot express the holder) — fixed.** `DomainVocabulary` now owns three named, distinct sets — the form's five dimensions, the filter state's extra holder dimension, and the directory's own holder-search dimension — and ADR-014 states the distinction and its rationale. `CountingQuery` owns the searched-population figure, so ADR-003's "none of them computes a count of its own" survives. The consequence is R-3 above, not a failure of the fix.
- **R-04 (delete refusal unowned) — fixed, but the fix is internally contradictory.** `AssetLifecycle` owns the refusal with a named code, which is the right structural move (ADR-006's "remove the capability rather than document a prohibition"). The contradiction is R-2 above.
- **R-05 (mermaid contradicting the yaml) — fixed and verified by parsing.** I extracted the yaml block and the mermaid block and compared the edge sets: **57 edges in each, and the sets are identical** — no edge in the diagram that is not in the catalogue, none in the catalogue that is not in the diagram. The two-node cycle (`AQ --> CQ` plus `CQ --> AQ`) is gone, and the previously missing `SP --> AR` edge is present. I also ran an independent acyclicity check over the catalogue's own dependency graph: **no cycles**, so the file's "The graph is acyclic" claim is now true.
- **R-06 (unowned `busy_timeout`; unsupported `ActorResolver → DomainVocabulary` edge) — fixed.** `DatabaseConnection` now owns the connection-level pragmas, including "The explicit, non-zero busy timeout", with ADR-013 giving the reasoning that the pragma is connection-level and therefore has to have one owner. The `ActorResolver → DomainVocabulary` edge is gone, `ActorResolver` is a true leaf, and the catalogue states why the earlier justification did not hold ("The earlier draft justified the edge as classifying the action an actor is attributed to, and no requirement asks for that"). I confirmed the underlying factual claim against the code: `busy_timeout` is indeed never set in `src/`.
- **R-07 (Unassigned designation not reserved) — fixed.** The display-holder rule now states all three things ADR-015 requires, including that the reserved designation "applies only to an asset that has **never** been held by anyone" and is "held as a distinct value rather than as a holder name that happens to read 'Unassigned'". This also correctly accommodates the never-held `lost` asset that the seed in `stories.md:63-107` requires to fall in the "Unassigned" row.
- **R-08 (list and export not peers) — fixed.** ADR-003 now carries an explicit "Being a peer is not the same as being independent" paragraph that names the one-way `AssetListScreen → CsvExport` edge and explains it, and ADR-010 repeats the position.

**Structural checks I performed independently, all passing:** the yaml block parses; 21 components with unique names; every `component:` and `owned_by:` reference resolves to a declared component; no self-dependency; `depends_on` and `dependents` symmetric on all 57 edges; each entity owned by exactly one component with an identifier; every `references.entity` declared under its stated `owned_by`; the graph acyclic; all five database entries correctly in `external_dependencies` rather than as components; the Component Summary and Entity Ownership tables reconcile exactly with the yaml; the traceability file's 40 `upstream_ids` match exactly the id set extracted from `stories.md` by independent regex, all 40 have coverage rows, and every coverage target names a component that exists in the catalogue; and the three framework sensors (`required-sections` on both deliverables, `traceability`, `upstream-coverage`) all fire and pass.

**Factual claims about the existing codebase that I checked against the source and confirmed accurate:** `INVALID_STATE` is thrown but unmapped in the middleware (`src/app.js:20` handles only four codes); `busy_timeout` is never set in `src/`; `DUPLICATE_ASSET` is raised from the unique-index violation (`src/repositories/assets-repo.js:70-73` matches on error *message* text, which the standing condition forbids — a point the design correctly intends to change); no delete path exists for assets; and the migration-ordering constraint the catalogue relies on is recorded in `architecture.md` as verified.

**Why the verdict is NOT-READY.** R-1 and R-2 are contradictions with binding upstream contracts and with the document's own ADR, in the two sections where the design states its most consequential decisions — the error vocabulary. R-3 is an unmet acceptance criterion reachable through a navigation the release itself introduces. R-4 is a stale count in the record that defines the catalogue's scope. R-5 and R-7 are design defects worth correcting now and cheap to correct now; R-6 is worth a decision. None of them requires re-opening the approved scope: R-1 and R-2 are corrected by making the design say what the upstream contracts already say, R-3 by one stated sentence, R-4 by one numeral, and R-5 by deleting one edge and reading the table from the leaf that already owns it.
